# Settlement reconciliation safety boundary

Money remains disabled by default. `FinancialNativeVerified` stays false and `RAID_FINANCIAL_ENABLED` is separately required. This implementation is not native financial acceptance and must not be enabled based on model tests.

The sole native owner appends original request, key, fingerprint, session and native snapshot to `settlement-recovery.jsonl` before sending a financial request. The append-only checksummed journal uses exclusive ownership and synchronous flushes. It must be on a persistent writable volume; preserve its journal and lock path across deployment. A corrupt, torn, locked or unwritable journal closes financial admission and blocks actor value rather than silently creating an empty ledger. Filesystem directory-entry/power-loss durability still requires an explicitly verified volume policy.

A verified backend proof is durable locally before the native economic boundary. The backend mirrors snapshot and consumption intent before mutation; local ConsumptionStarted is flushed before model grant/consumption and Consumed before cleanup. Identical callback retries from Consumed perform cleanup only. Completed callbacks acknowledge only. HTTP success alone is never economic authority. A crash at an ambiguous boundary quarantines instead of replaying consumption, refunding, minting or granting again.

Cleanup must verify money projection or retained original handle absence, empty actor inventory and spectator isolation. Exceptions and no-op native effects cannot acknowledge cleanup. Failed durable writes poison recovery immediately. Cleanup evidence is a durable outbox and can be mirrored again after restart without economic replay.

Deadlines close admission before fallible snapshots. Only the matching window's pending extractions retain its issued intent; unrelated pending operations do not block the cohort. Snapshot failure admits no payout or consumption for that actor/window and explicitly requires a future-window retry. A bounded pending timeout tombstones uncertain actors. Affected identities remain blocked through reset/reconnect while unaffected match state progresses. Retained original handles are still enforced from durable records; pickup denial is independent of active-match admission. Native isolation is not proven by these source paths.

Admin quarantine uses the separately configured recovery credential. It first persists quarantine_requested and a revocation epoch, blocking further execution and phase advancement, then looks up the ORIGINAL upstream key. Missing receipts never authorize compensation. Native observes that request on its sole game thread, durably tombstones before any later finalize, verifies physical isolation and sends a key/fingerprint/original-session/epoch-bound acknowledgement. Only that acknowledgement makes backend quarantine terminal. Reordered or repeated requests do not grant money, release claims or mark economic cleanup complete. Timeout and missing ownership remain unresolved, never terminal by absence.

Persisted raw native handles are generation-local. After a map transition/restart, this implementation deliberately refuses automatic old-generation removal or terminal acknowledgement, rather than deleting unrelated recycled handles. These cases require an explicitly verified recovery workflow that is not provided here. Operators must preserve the journal, immutable original identity and canonical receipt; no arbitrary-receipt or compensation API exists.

Required acceptance still includes isolated real-server crash/failure injection at every boundary, two-user reconnect/death/map unload and late callbacks, retained/ownerless item isolation across resets, native input/utility provenance, original upstream idempotency and single-owner deployment enforcement. Backend and extracted native/model tests do not establish these guarantees. No production/SSG changes are authorized by this branch.
