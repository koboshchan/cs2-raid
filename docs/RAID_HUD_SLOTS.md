Raid HUD slot contract, confirmed November 6, 2026.

This is design intent for the actual raid, not a report of implemented or deployed behavior. It supersedes any earlier extraction target that proposed reusing the native warmup timer. This change is documentation only. Debug previews are not proof that RaidPlugin implements this contract.

Container opening uses the CENTER CSS/HTML slot for the hold-E progress/countdown. It must NOT use ALERT. Retain the existing design durations of 5 seconds for normal containers, 10 for small safes and 17 for big safes, with release/moving-away cancellation. This slot choice does not implement the hold interaction or change reward/state rules.

ALERT is reserved exclusively for discrete teammate KNOCKED DOWN, extraction point OPENED, MONEY GAINED, and winning/extraction-payout events. Each such event must ALSO print its corresponding message to chat visible ONLY to that receiving player. Use recipient-scoped delivery for both surfaces; no ChatAll, PrintToChatAll or broadcast event/chat for these notifications. Where multiple recipients are entitled to an event, address each separately rather than broadcasting. Recipient policy beyond the relevant player is not invented here. The extraction-point-OPENED event notification is distinct from the continuously updating extraction countdown.

Extraction needs its OWN persistent HUD. Use the native warmup HUD's UPDATE PATTERN only as a research reference: retain the presentation instance and update its text without recreating it, retriggering entrance animations or causing flashing on every update. NEVER hijack or reuse the actual warmup timer, warmup gamerules, or global round state. The extraction countdown must use neither ALERT nor CENTER HTML. Do not substitute either as an automatic fallback if the independent persistent HUD proves unavailable.

Feasibility remains UNPROVEN. Ongoing research must trace native Panorama event, convar and networked-field inputs, panel creation/update/cleanup lifecycle, and any required client assets. Server-plugin JavaScript injection is NOT assumed to exist or be sufficient. A native-looking preview or a targeted event transport API alone does not establish a separately owned persistent extraction HUD. Do not mutate shared warmup/round state to manufacture one.

A private Debug prototype may be considered if feasible, without a restart, under the separate research scope. This document does NOT authorize code changes, loading/reloading plugins, client injection, live testing or server actions. No prototype or no-restart delivery mechanism is claimed implemented by this commit.
